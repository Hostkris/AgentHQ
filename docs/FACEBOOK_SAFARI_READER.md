# Facebook sign-in and approved Safari reading

My Accounts → a saved Facebook profile has **Sign in to Facebook**, a copy-link fallback, a specific page URL and task form, and setup instructions for the free Userscripts Safari extension. Facebook owns its Safari cookies. Agent HQ never receives a Facebook password, cookie, browser session or OAuth token and cannot guarantee that Facebook keeps a session signed in. iOS can route links to an app or the default browser; copying the link into Safari is the fallback.

Riley handles these requests entirely through the text conversation. The owner can say “Check my Facebook profile,” respond to a profile-number or link question in the same thread when needed, and reply “approved” to the exact scoped request. A direct approval is parsed deterministically by the owner-authenticated server, never inferred by an AI. Ambiguous, quoted, conditional, stale, expired and repeated approvals cannot start another read. “Stop” or “denied” declines/revokes the identified request; “continue” can reconnect the same still-approved request after a connection problem. No visit to My Accounts is required; the old account form remains optional.

Each scope message has a stored `prompt_message_id` and renders its controls at the corresponding point in Riley’s iMessage-style transcript. Missing profile/page choices are stored in service-only `agent_social_read_chat_state`, bound to the owner and latest Riley question. If no profile is saved, Riley accepts the content link in chat and saves only a private profile label; it does not claim an authenticated Facebook connection. The existing installed v1.0 Safari userscript is unchanged. Typed approval automatically creates its expiring one-page handoff and opens the page. Connection failures are reported as Riley messages; they do not turn a saved approval into a failed owner message or resend an uncertain read. A short-lived owner-scoped return marker opens Riley’s thread when the owner follows the reader’s Agent HQ link; it contains only a request ID/time, never a capability or account credential.

The request and Approve/Deny card are saved under the owner's Agent HQ sign-in. A pending request expires after 24 hours; approval permits one analysis for 15 minutes. The server requires the current owner's approved, unexpired request, the exact normalized URL and a capture made after approval. It claims the request atomically before calling Groq. Repeated claims, denial, revocation, wrong pages and expired grants are rejected. Riley cannot send replies or publish content through this feature. Alex's operating instructions and execution guards are unchanged.

## Connected Safari flow (no capture copy/paste)

Install Userscripts on the iPhone/iPad, open it once, and enable its Safari extension. Allow it only on `hostkris.github.io` and the Facebook/Messenger domains needed. Open `https://hostkris.github.io/AgentHQ/safari/agent-hq-connected-reader.user.js` in Safari and use the Userscripts popup to install it. This is a separate script; the original manual reader remains available. Grant network access to the Agent HQ Supabase endpoint if Safari/Userscripts asks.

1. Open Agent HQ **in Safari**, sign in, and ask Riley to review Facebook in the conversation. Answer any profile/link questions there. The Home Screen PWA may not run Safari extensions.
2. Reply **approved** to Riley’s scoped question (or use the optional approval button). The chat starts the reader automatically. This explicitly authorizes automatically sending the loaded text from the exact approved URL to Riley through the existing Groq connection.
3. The script stores a one-page capability in Userscripts storage and opens the approved page in Safari. Sign into Facebook yourself beforehand. Keep Safari open and the approved page visible. A five-second stop window appears before reading starts.
4. The connector checks that permission is still active, captures loaded rendered text (excluding form fields, editable drafts and hidden elements), and submits it directly. There is no capture to copy or paste. Riley’s report is saved in the private Agent HQ thread; return there to view it.
5. Tap the reader’s **Agent HQ** link after it finishes to return to Riley’s conversation. The phone must display the Facebook tab during reading; this is not an invisible background account browser.
6. Each capability expires with its 15-minute approval. A new connection replaces the old capability for that request; analysis claims the request once. Revoke in Riley’s thread to block submission or saving a result. “Stop this read” stops local work; if already submitted, revoke in the thread too.

The bridge is a deterministic **single-page reader**, not a general browser agent: it cannot navigate through the account, click Facebook controls, load hidden messages, publish, send, or control the Facebook app. It does not retry uncertain network/provider outcomes. Different URLs require separate approvals. Additional sites/actions need their own tested adapters. There is no paid browser service, desktop dependency or new AI provider; existing Supabase/Groq quotas still apply, and existing billing status was not changed or independently verified.

### Capability authentication

The existing owner function keeps JWT verification and `getUser()`/owner-allowlist checks. Only that authenticated owner can issue a handoff for their approved request. A cryptographically random 256-bit token is returned once and only its SHA-256 hash is stored in the service-only `agent_social_read_handoffs` table. No owner JWT, Facebook cookie, password or service key is given to the extension. The token is held in the userscript’s isolated storage, never put into a URL, web localStorage or chat message. Supabase’s new `agent-safari-bridge` endpoint uses custom capability authentication (`verify_jwt=false`); both `check` and `analyze` must resolve a live hash and allowed owner. An exact URL and the existing atomic one-use approval claim gate all AI calls. Direct anon/authenticated table/RPC access is revoked. Reissued, used, expired or revoked tokens cannot authorize a new analysis. Content remains untrusted user-supplied evidence, not a verified Facebook account audit.

## Manual iPhone and iPad flow

1. Sign into Facebook in Safari using the My Accounts link. If iOS opens the Facebook app, copy the link and paste it into Safari.
2. Install Userscripts: https://apps.apple.com/us/app/userscripts/id1463298887 . Open it once, enable its Safari extension and allow only the Facebook/Messenger sites needed.
3. Open `https://hostkris.github.io/AgentHQ/safari/agent-hq-reader.user.js` in Safari, then use the Userscripts extension menu to install it.
4. Request a review from My Accounts or Riley's conversation. Confirm the exact page URL and task. Tap Approve reading in Riley's thread.
5. Open that exact page in Safari, load the relevant content, and tap Read for Agent HQ. Review/edit the visible text, then tap Copy capture.
6. Return to the approved card in Riley's thread. Paste the full capture and tap Share approved text & analyze. The report is stored in the private thread. Copy suggested text and post/send it yourself in Facebook.

The script reads only on a tap. It previews up to 24,000 characters of rendered text and strips tracking/credential parameters from the URL. It does not inspect cookies, storage, input values or hidden messages; it refuses visible password fields and sign-in/settings routes. It has no network permission, uploads, posting or Facebook-click actions. Reading text in this script is a user action; AI access occurs only after owner approval and manual submission to Agent HQ. A capture is user-supplied evidence, not independently verified Facebook data.

Facebook/Messenger may restrict what mobile Safari renders. This does not guarantee personal Messenger access, all comments, live insights, Page status or background monitoring. Approval does not open a browser or bypass a login wall. Use the exact page URL; Facebook redirects to a different profile/post/conversation require a new approval for that URL.

## Storage, provider and limits

`agent_social_read_requests` has owner-only SELECT RLS and no direct client writes. The service-only `agent_social_read_transition` RPC binds owner, saved profile, Riley conversation, page and task. Request/status messages and reports are saved; raw captures are passed to Groq for the approved analysis and are not retained in a capture table or logged by the function. The paste draft is held in page memory and cleared on sign-out. Review/delete unwanted text before sharing.

`agent-social-read` verifies `getUser()` and the existing owner allowlist; JWT verification remains enabled. It accepts no Facebook write operation and no external URL-fetching tool. It uses the existing Groq connection with no paid provider fallback or automatic retry, at most four analysis starts and eight requests per owner per hour. Existing provider billing is not independently verified by this feature. This adds no browser-hosting subscription; the reader works on the foreground Safari page.
